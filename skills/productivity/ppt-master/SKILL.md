# PPT Master:通用演示文稿制作与美化技能

> 目标:产出"内容有逻辑、视觉有设计、文件能直接打开且可继续编辑"的演示文稿。
> 核心理念:**先想清楚要说什么,再决定怎么呈现,最后用工具实现并亲眼检查。**

---

## 0. 速查:最重要的 12 条

1. 先问清用途、受众、时长、篇幅、品牌/模板,信息已给全则不追问,直接做并声明假设。
2. **一页一个观点**,标题写结论(完整判断),而不是话题词。
3. 先定结构(金字塔:结论先行 → 摘要 → 分论点 → 结论/下一步),再做页面。
4. 先定**设计系统**(配色、字体、字号阶梯、间距、母题),再做页面,全程不偏离。
5. 配色:一色主导(60–70%)+ 1–2 辅助 + 一个强调色,与主题强相关,别默认蓝。
6. 每页至少一个视觉元素(图表/图标/形状/图片),避免"标题+纯 bullet"。
7. 字号阶梯:标题 36–44pt;小节 20–24pt;正文 14–16pt;注释 10–12pt。不低于下限,放不下就**删字/拆页**。
8. 边距 ≥ 0.5";块间距 0.3–0.5" 且全程统一;留白是设计的一部分。
9. 版式要有变化(双栏、图标行、网格、大数字、对比、时间线),禁止全篇同一版式。
10. 图表保持**原生可编辑**,并做减法:有标题、有数据标签、低饱和网格线、单系列去图例。
11. 用代码生成时:基于**主题+版式+占位符**搭建结构化 deck,便于一处改样式全局生效。
12. **必须 QA**:内容检查 → 文件校验 → 渲染成图逐页目检(先查文字溢出)。没看过渲染图不算完成。

## 1. 工作流(按顺序执行)

### 步骤 1:需求澄清(最小化提问)
需要确认的信息(已知则跳过,缺失且影响大才问,一次最多问 1–3 个):

| 维度 | 要点 |
|---|---|
| 用途 | 决策、说服、汇报、培训、路演、复盘、答辩 |
| 受众 | 高管(少字重视觉)/ 专业同行(可多信息)/ 客户 / 学生 |
| 使用方式 | 现场演讲(靠讲解)还是会前阅读(页面需自解释) |
| 时长/篇幅 | 现场约 1.5–2 分钟/页,并为问答留时间 |
| 品牌与模板 | 是否有 logo、品牌色、字体、公司模板 |
| 语言与格式 | 中/英文;.pptx 还是其他;16:9 还是 4:3 |
| 素材 | 数据、文档、图片、参考风格 |

模糊但可推断时:**直接做,并在交付时一句话写明假设**。

### 步骤 2:内容与叙事
- 提炼**核心信息**(一句话:听完这份 PPT 受众应该记住/做什么)。
- 选结构,并匹配规模:
  - **金字塔**:结论 → 摘要 → 分论点 → 结论与行动项(通用首选)。
  - 短 deck 可省略开场与结尾页;长 deck 加章节分隔页。
  - 目标导向:决策 / 共识 / 激励 / 化解分歧 / 开启讨论,据此安排高潮与收尾。
- 先写**页面大纲**:每页 = 一句话标题(结论)+ 支撑要点 + 计划的视觉形式。
- 标题检验:只读所有标题,应能连成完整的故事线。

### 步骤 3:设计系统(详见第 3 节)
在写任何页面之前确定:配色、字体、字号阶梯、间距、母题、版式清单。

### 步骤 4:实现(详见第 5–6 节)
新建用脚本生成;改已有 deck 用解包编辑;读取用文本导出。

### 步骤 5:QA 三件套(详见第 7 节)
内容 QA → 文件 QA → 视觉 QA,修复后只重渲染改动页。

### 步骤 6:交付
- 给出文件,**简短**说明:页数、结构、主题风格、做过的假设、可调整点。
- 不写长篇事后解释;用户自己会打开看。
- 需要演讲辅助时,把讲稿放进**备注栏**,不要塞进页面文本框。

## 2. 内容设计原则

### 2.1 文字
- 标题写**判断/结论**:"华东区增长由复购驱动,新客贡献仅 18%",而非"销售分析"。
- 标题不以句号结尾;同类型页标题位置、字体、字号、对齐必须一致。
- 要点用短语/短句,每条 ≤ 2 行;每页正文通常 ≤ 5 条。
- 正文**左对齐**,只有标题/大数字/封面可居中。
- 长文本改造策略:提炼 → 分组 → 转图示/表格/对比,而非缩小字号。

### 2.2 数据与论证
- 一个图表只讲一件事;图上直接标注关键点(高亮系列、箭头、注释),引导读者看哪里。
- 大数字(Stat callout):60–72pt 数字 + 小号标签 + 一句解释。
- 来源/脚注放页面底部小字,避免与正文碰撞。

### 2.3 页面类型清单
封面 · 议程/摘要 · 章节分隔 · 内容页(多种版式)· 数据页 · 对比页 · 流程/时间线 · 案例/引述 · 结论与下一步 · Q&A/联系方式(按需)

## 3. 视觉设计系统

### 3.1 配色
- **与主题相关**:换成别的主题还能用,说明选得太泛。
- **主导原则**:一个主色占 60–70% 视觉权重;1–2 个辅助色;一个锐利强调色(仅用于关键信息)。
- **明暗结构**:
  - "三明治":封面 + 结尾深色,内容页浅色;
  - 或全程深色,营造高级感。
- 确保文字与背景**对比度充足**(含图标:深色图标放深底要加浅色圆底)。
- 无品牌指定时,背景用白色 `FFFFFF`;避免默认米色/奶油色(如 F5F5DC、FAF0E6)。

**参考配色**(主色 / 辅色 / 强调):

| 主题 | 主色 | 辅色 | 强调 |
|---|---|---|---|
| 午夜高管 | `1E2761` 藏青 | `CADCFC` 冰蓝 | `FFFFFF` |
| 森林苔藓 | `2C5F2D` | `97BC62` | `F5F5F5` |
| 珊瑚活力 | `F96167` | `F9E795` | `2F3C7E` |
| 暖陶土 | `B85042` | `E7E8D1` | `A7BEAE` |
| 海洋渐变 | `065A82` | `1C7293` | `21295C` |
| 炭灰极简 | `36454F` | `F2F2F2` | `212121` |
| 青绿信任 | `028090` | `00A896` | `02C39A` |
| 浆果奶油 | `6D2E46` | `A26769` | `ECE2D0` |
| 鼠尾草静谧 | `84B59F` | `69A297` | `50808E` |
| 樱桃醒目 | `990011` | `FCF6F5` | `2F3C7E` |

> 示例仅作灵感,必须按具体主题/品牌调整。

### 3.2 字体
- **跨设备安全字体**(渲染宽度稳定、Office 自带):Arial、Calibri、Cambria、Times New Roman、Courier New、Bookman Old Style、Century Schoolbook。
- 有个性又低风险的组合:**安全衬线标题(Cambria 等)+ 安全无衬线正文(Calibri/Arial)**。
- 中文场景:选目标机器必有的字体(如微软雅黑、思源/苹方按平台而定),并预留 10%+ 宽度冗余;中英混排时分别指定字体。
- 非安全字体(Georgia、Trebuchet MS、Impact、Arial Black、Garamond、Consolas、Palatino Linotype)可用于标题/点缀,但容器留约 10% 余量,且**不要相信预览里的文字是否溢出**。
- **不要默认 Aptos**(旧版 Office 缺失,且预览环境无等宽替代)。
- 全 deck 只用 **1–2 种字体**;字重/字号/颜色制造层级,而不是堆字体。

### 3.3 字号阶梯

| 元素 | 字号 |
|---|---|
| 页面标题 | 36–44pt 粗体 |
| 小节标题 | 20–24pt 粗体 |
| 正文 | 14–16pt |
| 图注/来源 | 10–12pt 弱化色 |
| 大数字 | 60–72pt |

新建 deck 不得低于:正文 14pt、注释 10pt。放不下 → 删字、放大容器、拆页。编辑已有 deck/模板时,沿用其原有字号。

### 3.4 间距与对齐
- 页面边距 ≥ 0.5";内容块间距 0.3–0.5"(全篇选定一个并统一)。
- 同类元素严格对齐(网格对齐),同类页面标题等高。
- 疏密有致:不要塞满每一寸。

### 3.5 视觉母题
选**一个**可识别元素并贯穿全篇:圆角图片框、彩色圆底图标、特定形状裁切、统一的卡片风格等。
**不要**用色条/强调线作为母题(见第 8 节)。

### 3.6 图片与图标
- 图片:高质量、与主题相关、风格一致;可用半出血(整边铺满)+ 内容叠加。
- 图标:统一风格(线性或实心二选一),放在彩色圆形底上,与小节标题并排。
- 抽象示意用基础形状自行绘制,优于低质量素材图。

## 4. 版式库(避免重复,轮换使用)

| 版式 | 适用 |
|---|---|
| 左文右图 / 右文左图 | 概念讲解、产品介绍 |
| 图标 + 文字行 | 3–5 个并列特性/步骤 |
| 2×2 / 2×3 网格卡片 | 并列要点、功能矩阵 |
| 半出血大图 + 内容叠加 | 封面、情绪页、案例 |
| 大数字(Stat callout) | 关键指标、成果 |
| 对比双栏 | Before/After、方案对比、优缺点 |
| 时间线 / 流程图 | 路线图、里程碑、操作流程 |
| 图表 + 洞察侧栏 | 数据分析页(图 60% + 结论 40%) |
| 引述/案例页 | 客户证言、关键观点 |
| 章节分隔页 | 长 deck 的节奏调节 |

卡片区分方式:**浅色底色块、轻微阴影、图标**;不要用边缘色条。

## 5. 数据可视化规范

1. **原生图表优先**:能用 PowerPoint 原生图表就不用图片,保持可编辑。仅在无原生形态时(桑基、网络、弦图)才用图片。
2. 默认图表是"裸"的,必须美化:
   - 标题、数据标签(`showValue`)、使用主题色板;
   - 弱化坐标轴文字色,网格线细且淡,去掉分类轴网格线;
   - 单系列关闭图例;
   - 强调关键系列/柱,其余灰化。
3. 全 deck 的图表标签**字体、颜色、字号一致**(仅在确需时例外:次坐标轴、深色柱上的标签)。
4. 图表类型选择:趋势→折线;比较→柱/条;构成→堆叠/饼(≤5 类);分布→直方/箱线;关系→散点。
5. 图上直接写结论(标题或注释),不要让读者自己找洞察。
6. 表格:控制行列数、表头加粗、斑马纹或细分隔线、数字右对齐;长表格拆页。

## 6. 实现指南

### 6.1 方案选择

| 任务 | 做法 |
|---|---|
| 新建 deck | 用 `pptxgenjs`(Node)或 `python-pptx` 脚本生成,按"结构化 deck"搭建 |
| 编辑已有 deck / 套模板 | 解包 → 编辑 `ppt/slides/slideN.xml` → 重新打包 |
| 读取内容 | `markitdown deck.pptx`;缩略图总览用缩略图脚本 |
| 转图片检查 | LibreOffice 转 PDF → `pdftoppm` 转 JPG |

> `.pptx` 本质是 ZIP 包里的一堆 XML。

### 6.2 结构化 deck(新建默认做法,除非用户只要一次性草稿)
1. **主题先行**:定义主题对象(名称、标题字体、正文字体、`dk1/lt1/dk2/lt2/accent1–6/hlink/folHlink` 颜色),所有颜色用**主题色引用**,不写死十六进制,这样改主题即可全局换肤。
2. **章节**:每个章节前 `addSection`,并给每页指定 `sectionTitle`,避免出现"Default-N"杂章节。
3. **版式(Layout)**:为每种页面框架定义一个版式——封面、章节页、仅标题、图表+说明、表格;深浅变体按需。标题/正文/图表等区域做成**命名占位符**,位置、字号、字重、颜色写在占位符上。页脚文字、logo、页码放在版式里,不在单页中重复。
4. **按名填充**:新建页时指定版式与章节,再向占位符写内容,不再手写位置、字号、颜色。
5. **版式只是框架**:卡片、图标、数字卡片、图片仍在单页中叠加,并给每个对象命名(`objectName`)。
6. **先写文件、再应用主题**:生成 deck 后再把主题色写入文件,否则主题色引用会落到默认 Office 色板。

### 6.3 pptxgenjs 易踩坑(重要)
- **先设 `pres.layout`,再加页**。默认 `LAYOUT_16x9` 是 **10" × 5.625"**;`LAYOUT_WIDE` 是 13.3" × 7.5"。超出画布的坐标不会被截断,只会"消失"。
- **颜色**:不要 `#`,不要 8 位十六进制(都会损坏文件)。透明度用 `transparency: 0–100`(填充/图片)或 `opacity: 0–1`(阴影),二者不通用。
- **选项对象会被原地修改**(转成 EMU)。不要在多个 `add*` 调用间共用同一个 `shadow`/options 对象,每次新建。
- **阴影 `offset` ≥ 0**,负值损坏文件;想向上投影用 `angle: 270` + 正 offset。
- 字间距选项是 **`charSpacing`**,`letterSpacing` 会被忽略。
- **列表**:用 `bullet: true`,不要手打 `•`(会双重项目符号);除最后一项外每项设 `breakLine: true`;段间距用 `paraSpaceAfter`,不要用 `lineSpacing`。
- **一个输出文件一个 `new pptxgen()`**,不要复用实例。
- **`rectRadius` 仅对 `ROUNDED_RECTANGLE` 生效**。
- **不支持渐变填充**:用渐变图片做背景。
- 非占位符的 `addText` 需要 `isTextBox: true`(无障碍:否则读屏软件把它当"图形")。
- 文本框自带内边距:要与形状/线/图标对齐时设 `margin: 0`。
- **讲稿用 `slide.addNotes("...")`**,不要放进页面文本框。
- **图表**:
  - 堆叠柱/条图的 `dataLabelPosition` 只能是 `ctr`/`inEnd`/`inBase`,`outEnd` 会损坏文件;
  - 组合图使用次坐标轴时,必须同时提供 `valAxes` 与 `catAxes`(各 2 项),否则 PowerPoint 会丢弃该图表并提示文件损坏;
  - 图表文字默认写死 Arial,可将 `*FontFace` 设为 `"+mn-lt"`(主题正文字体)/`"+mj-lt"`(标题字体)。
- **不要调整 `<p:presentation>` 子元素的顺序**,否则文件可能无法打开。
- **图标**:用 `react-icons` 渲染 SVG → `sharp` 以 ≥256px 栅格化 → `addImage({ data: "image/png;base64," + base64 })`(前缀必需)。
- `defineSlideMaster()` 实际创建的是**版式(layout)**而不是母版,对用户沟通时称"版式"。
- `pres.company`、版式 `title` 中的 `&` 要写成 `&amp;`(其他如标题、作者、备注、页面文字会自动转义)。

### 6.4 编辑已有 deck / 套用模板
- 先看缩略图和文本导出,**为每个内容段落选模板页**;版式要有变化,别全用"标题+要点"。
- **结构性操作(增/删/排序)先于内容编辑**:复制页面后再改内容;否则复制的是已改内容。删页后再清理孤儿资源。
- 用专用脚本复制页面(处理所有关系登记);手工复制文件会出错。复制页仍会**引用**原页的图表/对象,改一处会影响另一处。
- 模板槽位 ≠ 内容条数:模板有 4 个头像而你只有 3 个,要删掉整个第 4 组(图片+文字),而不仅是清空文字。
- 脚本改 XML 时用安全解析器(如 `defusedxml.minidom`),不要用 `ElementTree` 往返(会改写命名空间前缀,损坏文件)。
- 一个列表项对应一个段落 `<a:p>`,不要合并;复制相邻段落格式;标题与行内标签加粗。
- 项目符号继承版式;仅在覆盖时才用 `buChar`/`buAutoNum`/`buNone`,文本里不手写 `•`。
- 首尾有空格的文本需要 `xml:space="preserve"`。
- 打包:**在解包目录内**执行 zip,并先删除旧输出文件;`.potx` 模板扩展名保持不变。
- 旧版 `.ppt` 先转换为 `.pptx`。
- 套模板后检查残留占位文本(lorem、ipsum、xxx、TODO、[insert…])。

### 6.5 美化已有 PPT(改版工作流)
1. **诊断**:导出文本+缩略图,列出问题清单——层级混乱、字体/字号不一、颜色杂、对齐差、文字墙、无视觉元素、版式重复、图表默认样式。
2. **保内容、改形式**:不擅自改动事实与数据;结构调整需说明。
3. **建立统一系统**:确定配色、字体、字号阶梯、间距,批量套用到所有页。
4. **逐类处理**:
   - 文字墙 → 提炼标题结论 + 分组 + 图示;
   - 纯 bullet → 图标行/卡片/网格;
   - 默认图表 → 按第 5 节美化;
   - 不对齐 → 以网格重排;
   - 低质量图片 → 替换或裁切统一。
5. **保持可编辑**:不要把整页烤成图片。
6. 做完走 QA 三件套,并对比前后缩略图。

## 7. QA(必须执行)

> 第一次渲染几乎总有真实问题:重叠、溢出、错位。修复后只重渲染改动页,然后停止,不要无限打磨。

### 7.1 内容 QA
- 导出文本,检查缺内容、错别字、顺序、数据一致性、标题故事线。
- 模板场景:搜索残留占位符。

### 7.2 文件 QA
- 运行校验脚本(结构、关系、内容类型、图表、slide XML)。模板衍生的 deck 要带 `--original` 基线对比。
- 校验失败要在**生成器里修复**并重建,不要手改打包后的 XML。
- 注意:有些图表 XML 能被 LibreOffice/python-pptx 打开,但 PowerPoint 会拒绝,所以校验不可省。

### 7.3 视觉 QA(逐页看图)
转图命令:
```bash
python scripts/office/soffice.py --headless --convert-to pdf output.pptx
rm -f slide-*.jpg
pdftoppm -jpeg -r 150 output.pdf slide
ls -1 "$PWD"/slide-*.jpg
```
修复后**四条命令全部重跑**(PDF 必须由新 pptx 重新生成)。

逐页检查清单:
- [ ] **文字溢出/被截断**(最常见,最先查)
- [ ] 元素重叠(文字穿过形状、线穿过字、叠放)
- [ ] 来源/页脚与正文碰撞
- [ ] 元素间距 < 0.3",卡片贴得过近
- [ ] 间距不均(此处空旷、彼处拥挤)
- [ ] 边距 < 0.5"
- [ ] 列/同类元素未对齐
- [ ] 低对比度文字或图标
- [ ] 模板装饰位置错位(如标题换行后下划线位置不对)
- [ ] 文本框过窄导致过度换行
- [ ] 同类页标题高度/图表标签样式不一致(横向对比各页)
- [ ] 单词或数字被拆行("26" 与 "M" 分两行)
- [ ] 残留占位内容

提示:盯着生成代码太久会"脑补"结果,务必**用新眼光看渲染图**(如有子代理可交给它看)。字体替换导致的预览偏差,以第 3.2 节的冗余规则为准。

## 8. 避坑清单(Avoid)

- ❌ 全篇同一版式
- ❌ 纯文字页(标题+纯 bullet)
- ❌ 标题以句号结尾;同类页标题位置/字号漂移
- ❌ 正文居中(只居中标题)
- ❌ 字号对比不足(标题需 36pt+ 对比 14–16pt 正文)
- ❌ 默认蓝 / 默认米色背景
- ❌ 间距随意混用
- ❌ 只美化一页、其余保持素页(要么全做,要么全简)
- ❌ 图表间标签样式不一致
- ❌ 忘记文本框内边距导致对不齐
- ❌ 低对比度文字或图标
- ❌ **标题下方的装饰线**(典型"AI 味")
- ❌ **装饰色条/强调条**:通栏页眉页脚条、侧边竖条、卡片单边色条、矩形单边边框——一律不用;用淡底色、阴影、图标代替
- ❌ 文字溢出形状;为塞内容把字号缩到下限以下
- ❌ 把整页做成不可编辑的图片
- ❌ 讲稿塞进页面文本框(应放备注)
