# Structure Models in Detail

Four classic structural frameworks for carrying the content of different page types. **Choosing the wrong framework is more fatal than ugly layout.**

| Model | Core use | Typical slide count |
|---|---|---|
| **5W2H** | Describing one thing completely | 1–3 slides |
| **SWOT** | Strategic positioning analysis | 1–2 slides |
| **Funnel** | Conversion and filtering | 1 slide |
| **Timeline** | Evolution and planning | 1–2 slides |

---

## 1. 5W2H

### 1.1 The seven elements

Used to describe one thing completely and make sure no information is missing.

| Element | English | Question | Notes |
|---|---|---|---|
| **What** | What | What it is / what to do | Goal, content, subject |
| **Why** | Why | Why do it | Background, necessity, value |
| **Who** | Who | Who does it / who it's for | Team, owner, audience |
| **When** | When | When | Milestones, cycle, deadline |
| **Where** | Where | Where | Region, scenario, channel |
| **How** | How | How to do it | Method, path, technical approach |
| **How much** | How much | How much | Budget, resources, quantity, metrics |

### 1.2 Why it works

**It answers MECE's "collectively exhaustive" requirement.**

If all seven elements are spelled out, the information is complete. Conversely, if a proposal is challenged as "unclear," it is usually because one element is missing.

### 1.3 Choosing by scenario

You don't need all seven. Choose by scenario:

#### Project kick-off

| Element | Content |
|---|---|
| **Why** | Why this project |
| **What** | Project goals and deliverables |
| **How** | Technical route and implementation plan |
| **How much** | Budget and resource requirements |
| When | Key milestones (can be simplified) |

#### Execution plan

| Element | Content |
|---|---|
| **What** | Specific tasks |
| **Who** | Owner |
| **When** | Milestones |
| **How** | Execution method |

> An execution plan is essentially a matrix of "task + owner + time."

#### Problem analysis

| Element | Content |
|---|---|
| **What** | Symptoms of the problem |
| **Why** | Root cause |
| **Where** | Scope of impact |
| **How much** | Quantified loss |

#### Product / service introduction

| Element | Content |
|---|---|
| **What** | What the product is |
| **Who** | Who it suits |
| **Where** | Use scenarios |
| **How much** | Price / return |

#### Proposal statement (full version)

All seven elements, suitable as the "overview slide" of a proposal.

### 1.4 Laying it out in a deck

**Layout 1: seven-grid**

```
┌────────┬────────┬────────┐
│  What  │  Why   │  Who   │
├────────┼────────┼────────┤
│  When  │ Where  │  How   │
├────────┴────────┴────────┤
│       How much           │
└──────────────────────────┘
```

**Layout 2: three columns** (trimmed to 4–5 items)

```
┌───────────┬───────────┬───────────┐
│  Why do   │  What to  │  How to   │
│    it     │    do     │   do it   │
└───────────┴───────────┴───────────┘
```

**Layout 3: lead-in paragraph + table**

Suits proposal overview slides with a lot of information.

### 1.5 How to check

**Reverse self-check**: after finishing a slide, ask yourself—

- [ ] Does the audience know **what to do**? (What)
- [ ] Do they know **why to do it**? (Why)
- [ ] Do they know **who is responsible**? (Who)
- [ ] Do they know **when it will be finished**? (When)
- [ ] Do they know **where it happens**? (Where)
- [ ] Do they know **how to do it**? (How)
- [ ] Do they know **how much it costs**? (How much)

Fill in whichever one is missing—or state explicitly that this slide doesn't need it.

## 2. SWOT

### 2.1 Basic structure

```
┌────────────────────────┬────────────────────────┐
│   S Strength           │   W Weakness           │
│   Internal · Positive  │   Internal · Negative  │
│                        │                        │
├────────────────────────┼────────────────────────┤
│   O Opportunity        │   T Threat             │
│   External · Positive  │   External · Negative  │
└────────────────────────┴────────────────────────┘
```

### 2.2 The two dimensions

| Dimension | Distinction |
|---|---|
| **Internal / external** | What I can change vs what I can't |
| **Positive / negative** | Favourable vs unfavourable |

**Test**: if your side can directly control the factor, it is an internal factor.

| Internal factors (S/W) | External factors (O/T) |
|---|---|
| Team capability, funding, technology | Market trends, policy, competition |
| Brand, channels, customer relationships | Shifts in customer demand, technological change |
| Management systems, process efficiency | Economic environment, industry standards |

### 2.3 The key: SWOT's value is in the combinations

> ⚠️ **The most common mistake**: listing only S/W/O/T and giving no strategic conclusion.
>
> **SWOT is not four parallel items; it is four types of strategy formed by pairing them up.**

| Combination | Strategy | Direction | Example |
|---|---|---|---|
| **SO** | Growth | Use strengths to seize opportunities | Technical advantage + a growing market → invest more and expand |
| **WO** | Turnaround | Fix weaknesses to seize opportunities | No channel + new demand → bring in partners |
| **ST** | Diversification | Use strengths to avoid threats | Cost advantage + intensifying competition → fight on price to defend share |
| **WT** | Defensive | Reduce weaknesses, avoid threats | Weak capability + a shrinking market → scale back and control costs |

### 2.4 Laying it out in a deck

**Layout 1: classic four quadrants** (analysis only)

```
┌────────────────────────┬────────────────────────┐
│   S Strength           │   W Weakness           │
│   · …                  │   · …                  │
├────────────────────────┼────────────────────────┤
│   O Opportunity        │   T Threat             │
│   · …                  │   · …                  │
└────────────────────────┴────────────────────────┘
```

**Layout 2: four quadrants + strategy band** (recommended, expresses the whole thing)

```
┌────────────────────────┬────────────────────────┐
│   S Strength           │   W Weakness           │
├────────────────────────┼────────────────────────┤
│   O Opportunity        │   T Threat             │
├────────────────────────┴────────────────────────┤
│ SO Growth │ WO Turnaround │ ST Diversify │ WT Defend │
└─────────────────────────────────────────────────┘
```

**Layout 3: TOWS matrix** (strategy first)

Put the four strategy types in the main position and use S/W/O/T as support.

### 2.5 Four requirements

| Requirement | Notes |
|---|---|
| **Elements are concrete** | Write "a 200-person R&D team", not "strong R&D capability" |
| **Elements are verifiable** | Backed by data or facts |
| **Cap the number** | 3–5 per quadrant (Hick's law) |
| **Strategies are mandatory** | At least one strategy for each of SO/WO/ST/WT |

## 3. Funnel

### 3.1 Basic structure

```
    ████████████      Layer 1 (largest)
     ██████████
      ████████
       ██████
        ████          Last layer (smallest)
```

### 3.2 Two ways to use it

#### Filtering type

**Meaning**: narrowing layer by layer; the survivors win. Focus on "what is left in the end."

| Application | Example layers |
|---|---|
| Recruiting | Applications → Screening → Interviews → Hire |
| Quality control | Full inspection → Sampling → Re-inspection → Shipment |
| Supplier onboarding | Qualification review → Site visit → Trial → Approval |

#### Conversion type

**Meaning**: drop-off at each layer; focus on the conversion rate. **The point is analysing the drop-off.**

| Application | Example layers |
|---|---|
| Marketing conversion | Reach → Interest → Intent → Purchase → Repurchase |
| Customer journey | Awareness → Consideration → Decision → Use → Loyalty |
| Sales process | Lead → Opportunity → Quote → Contract → Payment |

### 3.3 Key requirements

| Requirement | Notes |
|---|---|
| **Values are mandatory** | Label each layer with a count or percentage, otherwise the funnel is meaningless |
| **Cap the number of layers** | 3–5 layers (Hick's law) |
| **Highlight the bottleneck** | Use an accent colour to mark the layer with the worst drop-off |
| **Label conversion rates** | Show the conversion percentage between layers |

### 3.4 Laying it out in a deck

**Layout 1: standard funnel chart**

```
        ┌───────────────┐
        │  10000 Reach  │
        └───────┬───────┘
          ↓ 30%
       ┌──────────────┐
       │ 3000 Interest│
       └───────┬──────┘
          ↓ 20%
       ┌────────────┐
       │ 600 Intent │
       └──────┬─────┘
          ↓ 50%
       ┌──────────┐
       │ 300 Deal │
       └──────────┘
```

**Layout 2: horizontal funnel bars** (suits widescreen)

```
Reach     ████████████████████████  10000
Interest  ███████                   3000  ↓30%
Intent    ████                       600  ↓20%
Deal      ██                         300  ↓50%
```

**Layout 3: funnel + improvement actions**

Funnel on the left, improvement plans aimed at the bottleneck layer on the right. **This is the most valuable version**—it doesn't just describe the current state, it gives actions.

### 3.5 Common mistakes

| Mistake | Problem | Fix |
|---|---|---|
| No values | Purely decorative graphic | Label each layer with a count and conversion rate |
| Too many layers | 7–8 layers, hard to read | Merge down to 3–5 layers |
| Equal-width layers | Can't express narrowing | Draw the widths in proportion |
| No conclusion | Describes without analysing | Mark the bottleneck + improvement actions |

## 4. Timeline

### 4.1 Four forms

#### Form 1: horizontal linear axis

**Most common.** Good for showing milestones.

```
●────────●────────●────────●────────●
2020     2021     2023     2025     2026
Founded  Funded   Expanded Pivoted  Listed
```

- 3–7 nodes
- Alternate labels above and below the axis (to avoid crowding)
- Use for: company history, brand milestones

#### Form 2: vertical timeline

Suits cases with more content where each node needs a detailed explanation.

```
│
├─● 2020  Company founded
│         Angel round raised
│
├─● 2022  Series A closed
│         Team grew to 200
│
├─● 2024  Headquarters campus opens
│         Entering a second start-up phase
```

- Use for: company history, project retrospectives

#### Form 3: Gantt chart

Can express task **parallelism and duration**.

```
           Jan  Feb  Mar  Apr  May  Jun
Requirements ████
Design           ██████
Development          ██████████
Testing                     ████
Launch                          ██
```

- Bars represent time spans
- Can show dependencies
- Use for: project scheduling, implementation plans

#### Form 4: stepped axis

Uses height differences to express **phase-by-phase leaps**.

```
                              ┌─── 2026 Listed
                    ┌─────────┤
          ┌─────────┤  2024 Pivot
┌─────────┤  2020 Expansion
│  2015 Start
└─
```

- Use for: emphasising growth, phase breakthroughs

### 4.2 Advanced techniques

**Growing node size**: use the size of the shape to imply growth, with no words needed.

```
  ●  →   ●●  →   ●●●●  →  ●●●●●●
 Start   Growth  Expansion  Maturity
```

This is a textbook case of "visual expression beats words."

### 4.3 Key requirements

| Requirement | Notes |
|---|---|
| **≤ 7 time points** | Hick's law |
| **Clear tick labels** | Year / quarter / month |
| **Distinguish done from planned** | Use dashed lines or a light colour for future nodes |
| **Every node must carry an event** | Don't add fields just to make up the numbers |
| **Keep labels short** | ≤ 15 characters per node |

### 4.4 Combining with other frameworks

| Combination | Use |
|---|---|
| Timeline + 5W2H | Project plan (the timeline shows the nodes, 5W2H explains the content of each) |
| Timeline + funnel | Customer journey (time on the horizontal axis, conversion on the vertical axis) |
| Timeline + pyramid | Strategic roadmap (the timeline shows the phases, the pyramid shows the goal hierarchy) |

## 5. Structure selection decision tree

```
What is this slide trying to express?
│
├─ Describe one thing completely ─────────→ 5W2H
│   ├ Project kick-off → Why/What/How/How much
│   ├ Execution plan → What/Who/When/How
│   ├ Problem analysis → What/Why/Where/How much
│   └ Proposal overview → all seven elements
│
├─ Strategy / competitive analysis ───────→ SWOT
│   ├ Analysis only → four quadrants
│   └ Need strategies → four quadrants + SO/WO/ST/WT
│
├─ Conversion / filtering process ────────→ Funnel
│   ├ Focus on the outcome → filtering type
│   └ Focus on drop-off → conversion type + improvement actions
│
├─ Time evolution / planning ─────────────→ Timeline
│   ├ Milestones → horizontal linear axis
│   ├ Detailed history → vertical timeline
│   ├ Project schedule → Gantt chart
│   └ Phase leaps → stepped axis
│
└─ Other common structures
    ├ One idea / a key line → single paragraph / full-bleed image
    ├ 2–4 parallel points → MECE classification + parallel layout
    ├ Process / steps → progressive logic diagram (one-way arrows)
    ├ Closed loop → circular logic diagram
    ├ Data comparison → data comparison layout / bar chart
    ├ Trend → line chart
    ├ Composition → pie / donut chart (≤5 slices)
    └ Hierarchy → architecture diagram / pyramid diagram
```

## 6. How the four models work together

In a real proposal, the four models are usually used together:

```
Overall proposal
├─ Opening: SCQA (logic layer)
├─ Background and goals: 5W2H (spell out what, why and how)
├─ Current-state analysis: SWOT (position strengths and weaknesses)
├─ Current-state data: funnel (quantify conversion/filtering)
├─ Implementation plan: timeline (schedule and milestones)
└─ Closing: conclusion + next steps
```

**A sample skeleton for a complete proposal**:

| Slide | Content | Framework |
|---|---|---|
| 1 | Cover | — |
| 2–3 | Background and problem | SCQA (S + C) |
| 4 | Proposal overview | SCQA (A) + 5W2H |
| 5 | Current-state analysis | SWOT (with strategies) |
| 6 | Current-state data | Funnel |
| 7–10 | The concrete proposal | MECE sections + Pyramid |
| 11 | Implementation plan | Timeline / Gantt chart |
| 12 | Summary and next steps | Pyramid (conclusion first) |
