# Delivery Checklist

Go through the items in order. **If any item fails, do not deliver.**

The checks are organised around three layers of theory: **logic layer → visual layer → structure layer → delivery layer**.

---

## I. Logic Layer Checks

> Theoretical basis: Pyramid Principle · MECE · SCQA (see `logic-frameworks.md`)

### Pyramid Structure

- [ ] There is one sentence that captures the core conclusion of the whole deck
- [ ] Every page title is a **conclusion sentence**, not a noun phrase
- [ ] **Title test passes**: reading all page titles in sequence forms a complete storyline
- [ ] Each page's content supports that page's conclusion (the top governs the bottom)
- [ ] Evidence supports the conclusion, with no logical leaps
- [ ] Items within a group follow an explicit order (time / structure / importance)

### MECE Check

- [ ] Parallel items **do not overlap** (can any one item belong to two groups at once?)
- [ ] Parallel items have **no gaps** (is any content left without a home?)
- [ ] Number of parallel items ≤ 5 (2–4 recommended)
- [ ] The table-of-contents chapter breakdown is MECE
- [ ] Table header columns are mutually exclusive

### SCQA Opening

- [ ] The opening has a Situation (S) that builds common ground
- [ ] The opening has a Complication (C) that creates tension
- [ ] The complication raises a clear Question (Q)
- [ ] The Answer (A) is the main thread of the deck and maps to the following chapters
- [ ] The situation description stays within half a page

### Content Quality

- [ ] The script can be delivered without looking at the PPT (the PPT supports, it is not the script)
- [ ] Each page makes only **one point**
- [ ] Chinese character count per page ≤ 100
- [ ] No whole paragraphs copied from the document
- [ ] No piles of bare bullets (more than 5 bullets means reconsider the layout)

### Accuracy

- [ ] No typos
- [ ] No leftover placeholders ("main title here", "XX Company", "click to add text")
- [ ] All entity names / project names / personal names / dates have been replaced
- [ ] Chapter numbers match the actual order
- [ ] Data is the latest version
- [ ] Every data point is labelled with its **cut-off date** and **source**
- [ ] No exaggeration, no misleading statements

## II. Visual Layer Checks

> Theoretical basis: Gestalt · Rule of Thirds · Hick's Law · CRAP (see `visual-theories.md`, `design-basics.md`)

### Gestalt: Grouping and Hierarchy

- [ ] Related content sits close together (proximity)
- [ ] Spacing within a group < spacing between groups
- [ ] Elements at the same level share the same specification (similarity)
- [ ] Icons of the same kind share one style (don't mix outline and filled)
- [ ] Grouping uses a backing panel or region (common region)
- [ ] Emphasis surfaces through contrast (figure/ground)
- [ ] The background does not steal attention from the subject

### Hick's Law: Cognitive Load

- [ ] Key points per page ≤ 5 (3 recommended)
- [ ] Table-of-contents chapters ≤ 5 (3–4 recommended)
- [ ] Lines on a chart ≤ 3
- [ ] Pie slices ≤ 5
- [ ] Table columns ≤ 7
- [ ] Colours per page ≤ 3
- [ ] Segments in a parallel layout ≤ 5
- [ ] Charts per page ≤ 3 (1 recommended)

### Rule of Thirds: Composition

- [ ] The main element avoids dead centre (not placed in the middle)
- [ ] Text-and-image mixes split 1/3 : 2/3
- [ ] On full-screen image pages the title sits at a visual focal point
- [ ] The visual centre of gravity is upper-middle or left-middle
- [ ] The page is broadly balanced (no side is overloaded)

### Type Size

- [ ] All type sizes sit on a scale (e.g. 54/40/32/24/18/16/14/12)
- [ ] Level ratio ≥ 1.5×
- [ ] Elements at the same level use exactly the same size
- [ ] Body text ≥ 14pt (reading version) / ≥ 18pt (auditorium version)
- [ ] Smallest type size ≥ 10pt
- [ ] Numbers on the same data page share one size and one weight
- [ ] When Chinese and English are mixed, Chinese is one step larger than English
- [ ] All-caps English has been reduced by 1–2pt

### Fonts

- [ ] No more than 2 font families
- [ ] Chinese fonts are set explicitly (including the `a:ea` attribute)
- [ ] No stray fonts mixed in (e.g. FangSong or DengXian appearing out of nowhere)
- [ ] Fonts are consistent throughout

### Colour

- [ ] Colours per page ≤ 3 (excluding black, white, grey)
- [ ] The primary colour takes up about 60%
- [ ] The accent colour is used in only the single most important place
- [ ] Body-to-background contrast ratio ≥ 4.5:1 (≥ 7:1 recommended for auditoriums)
- [ ] Pure black `#000000` is not used as the body text colour
- [ ] The colour scheme is consistent throughout (no page suddenly switching palette)

### Alignment and Proximity (CRAP)

- [ ] Every element on every page can be traced to an alignment line
- [ ] No "roughly aligned" (the 2–3px drift the eye can't see)
- [ ] Elements at the same level align on their left edge / centre line
- [ ] The same kind of element sits in the same place across pages
- [ ] A title sits tight to its body text
- [ ] A caption sits tight under its image
- [ ] Gap between cards ≥ 1.5× the card's internal padding

### Contrast Strength

- [ ] Primary and secondary information contrast clearly (the **squint test** reveals the hierarchy)
- [ ] No weak contrast (e.g. 14pt vs 16pt)
- [ ] Contrast is achieved through at least two dimensions (e.g. size + colour)

### Whitespace and Safe Area

- [ ] Margins on all four sides ≥ 5% of page width
- [ ] Content occupies ≤ 70% of the layout
- [ ] There is a clear sense of visual breathing room
- [ ] All content sits inside the guides / safe area
- [ ] No element is clipped or runs off the canvas
- [ ] No element covers the fixed header/footer elements

## III. Structure Layer Checks

> Theoretical basis: 5W2H · SWOT · Funnel · Timeline (see `structure-models.md`)

### 5W2H Completeness (proposal / plan pages)

- [ ] Does the audience know **what is to be done**? (What)
- [ ] Do they know **why it is being done**? (Why)
- [ ] Do they know **who is responsible**? (Who)
- [ ] Do they know **when it will be finished**? (When)
- [ ] Do they know **where it will be done**? (Where)
- [ ] Do they know **how it will be done**? (How)
- [ ] Do they know **how much it will cost**? (How much)

### SWOT (if used)

- [ ] All four S/W/O/T quadrants are present
- [ ] Factors are specific and verifiable (write "R&D team of 200", not "strong R&D capability")
- [ ] 3–5 items per quadrant
- [ ] **The four SO/WO/ST/WT strategy types have been added** (critical!)
- [ ] Internal/external and positive/negative classifications are correct

### Funnel (if used)

- [ ] Each layer is labelled with a value or ratio
- [ ] The number of layers stays between 3 and 5
- [ ] Widths are drawn to true proportion
- [ ] The worst drop-off layer is marked
- [ ] Improvement measures are given (not just a description of the status quo)

### Timeline (if used)

- [ ] Time points ≤ 7
- [ ] Clear time ticks are labelled
- [ ] "Completed / planned" are distinguished
- [ ] Each node's content is brief (≤ 15 characters)
- [ ] The chronological order is correct

### Correct Choice of Framework

- [ ] Describing something in full → 5W2H was used
- [ ] Strategic analysis → SWOT was used and strategies were given
- [ ] Conversion / filtering → A funnel was used and values were labelled
- [ ] Evolution over time → A timeline was used
- [ ] No framework is misused (e.g. a pie chart to express a trend)

## IV. Asset Layer Checks

### Images

- [ ] Resolution ≥ 150 dpi (projection) / ≥ 300 dpi (print)
- [ ] No stretching or distortion (original aspect ratio preserved)
- [ ] No low-resolution images, no watermarked images
- [ ] Image style is consistent throughout
- [ ] Image tones harmonise with the colour scheme

### Charts

- [ ] The chart type is chosen correctly
- [ ] Simplification is done (gridlines removed, legend removed, axes muted)
- [ ] Data labels are present
- [ ] The chart carries an explicit conclusion (one sentence above or below it)
- [ ] Axis units are clear
- [ ] Pie slices ≤ 5

### Tables

- [ ] Three-line table format (no vertical rules)
- [ ] The table title sits above the table
- [ ] Numbers right-aligned, text left-aligned
- [ ] The header row is distinguished (fill or bold)
- [ ] Columns ≤ 7

### Icons

- [ ] Style is consistent
- [ ] Size is consistent
- [ ] Aligned to the text baseline

## V. Delivery Layer Checks

### Technical Checks

- [ ] **Fonts are embedded**
  - Windows: File → Options → Save → Embed fonts in the file
  - macOS: Preferences → Save → Embed fonts in the file
- [ ] A PDF backup has been exported (guards against fonts being lost across devices)
- [ ] Opened and verified on **another computer**
- [ ] Tested on the actual projector / large screen (is the type big enough)
- [ ] The file is not corrupted and no links are broken
- [ ] Audio and video assets are embedded, not externally linked

### File Conventions

- [ ] File name follows the convention: `project name+date`
- [ ] Version numbers are clear (avoid v1/v2/final/final-final/really-final)
- [ ] Draft pages, hidden pages and test pages are deleted
- [ ] Hidden slides are checked (drafts may be left behind)

### Presentation Preparation

- [ ] A **speaker version** (fewer words, larger type) and a **reading version** (complete information) are prepared
- [ ] The table-of-contents page numbers match the content
- [ ] The notes pane is filled with speaking points (if needed)
- [ ] Backup pages are prepared (questions that may come up)

## Three Quick Self-Checks

### 1. Squint Test

Squint (or shrink the slide to 25%) and look at each page.
- ❌ It is a blur and the structure is unreadable → insufficient contrast, unclear hierarchy
- ✅ The title area and content area are still distinguishable → contrast is right

### 2. One-Meter Test

Print the PPT and view it from one metre away.
- Alignment problems, uneven spacing and type that is too small jump out immediately
- This is the most effective way to catch "roughly aligned"

### 3. Three-Second Test

Show the deck to someone who has not seen it for 3 seconds, then ask: "What did you see? What is this page saying?"
- ✅ The answer matches your intent → pass (it also means Hick's Law is satisfied)
- ❌ They cannot answer or answer off-target → the visual focus is unclear and the page needs redoing

## Top 12 Reasons for Rework

| Rank | Problem | Layer | Fix |
|---|---|---|---|
| 1 | Too much text, reads like a document | Logic | Use the four-step method, cut 50% of the text |
| 2 | Type too small (< 12pt) | Visual | Raise to 14pt+, split the page |
| 3 | Too many colours (> 3) | Visual | Converge on one colour family |
| 4 | Inconsistent fonts | Visual | Use 2 font families throughout |
| 5 | Elements not aligned | Visual | Re-lay out with guides |
| 6 | Blurry images | Asset | Replace with high-resolution images |
| 7 | Titles are uninformative noun phrases | Logic | Rewrite as conclusion sentences |
| 8 | Data has no source or date | Logic | Add the labels |
| 9 | Forgot to embed fonts | Delivery | Embed and re-export |
| 10 | Placeholders not replaced | Logic | Search the whole file for "XX" and "here" |
| 11 | Parallel items not MECE | Logic | Choose a new classification dimension |
| 12 | SWOT lists without strategies / funnel without values | Structure | Add strategies / add values |

## Scenario Adjustments

### Auditorium Talk (viewed from 10 metres)

| Item | Adjustment |
|---|---|
| Body type size | ≥ 24pt |
| Words per page | ≤ 50 |
| Key points per page | ≤ 3 |
| Charts | Minimal, conclusion only |
| Page count | 1–2 pages per minute |

### Laptop / Video Conference

| Item | Adjustment |
|---|---|
| Body type size | 14–18pt |
| Words per page | ≤ 100 |
| Charts | Can be somewhat more detailed |
| Page count | Unrestricted |

### Email / Print Reading (no live delivery)

| Item | Adjustment |
|---|---|
| Body type size | 12–14pt |
| Information density | Can be higher, but must be **self-contained** |
| Every page must explain itself (it cannot rely on the speaker to fill gaps) |
| Add **page numbers** and a **header/footer** |
| Sending a PDF alongside is recommended |

> ⚠️ **Do not use one version for both purposes.** A speaker version packed with text cannot be read by the audience; a reading version with too few words cannot be understood.
> The right approach: build the reading version first (complete information), then cut it down into the speaker version.
